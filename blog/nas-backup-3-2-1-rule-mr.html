Small Business साठी NAS Backup: 3-2-1 Rule, सोप्या भाषेत

NAS (Network Attached Storage) ला बरेचदा backup समजलं जातं. ते तसं नसतं — तो shared storage असतो, आणि जर तोच तुझ्या data चा एकमेव copy असेल, तर एक device fail झाला, आग लागली, चोरी झाली, किंवा ransomware attack झाला तर सगळं एकाच वेळी संपू शकतं. Real backup strategy साठी एकापेक्षा जास्त copy, एकापेक्षा जास्त जागी लागते.

3-2-1 rule

  • 3 copies तुझ्या data च्या — original + दोन backups
  • 2 वेगवेगळे storage types — उदा. NAS + external drive किंवा cloud storage, एकाच प्रकारच्या device वर दोन copies नाही
  • 1 copy offsite किंवा offline — office पासून physically वेगळ्या जागी, किंवा network पासून disconnected, जेणेकरून local disaster किंवा सगळं reach करू शकणारा ransomware attack झाला तरी ती copy वाचते

"Offline" लोकांना वाटतं त्यापेक्षा जास्त का महत्त्वाचं आहे

Ransomware खास connected backups ना target करतो. तुझा NAS नेहमी network-accessible असेल, तर office network मधून पसरणारा एखादा infection live data आणि NAS वरचा backup दोन्ही एकाच वेळी encrypt करू शकतो. यातून वाचण्यासाठी किमान एक backup copy offline (disconnected) किंवा offsite (वेगळ्या physical location वर) असायलाच हवी.

Practical मध्ये हे कसं दिसतं

एका Synology NAS deployment मध्ये, setup मध्ये role-based, department-level access control होता — पण access control आणि backup या दोन वेगळ्या गोष्टी आहेत. Access control रोजच्या रोज कोण data पर्यंत पोहोचू शकतं हे ठरवतो; backup काहीतरी चुकलं तर काय होतं हे ठरवतो, त्यावेळी कुणाला access होता याचा संबंध नाही.

Small business साठी reasonable setup: रोजच्या shared storage साठी NAS, दुसऱ्या NAS किंवा external drive (वेगळं device) वर automated backup job, आणि office पासून physically वेगळ्या cloud storage किंवा drive वर periodic (आठवड्याला किंवा महिन्याला) copy.

सगळे skip करतात तो step

जो backup कधीच actually restore करून test केला नाही तो backup म्हणजे फक्त अंदाज आहे, plan नाही. दर काही महिन्यांनी random file निवड आणि backup मधून (live system मधून नाही) restore करून बघ — backup actually काम करतोय ना, चूपचाप fail तर होत नाहीये ना हे confirm करण्यासाठी.
